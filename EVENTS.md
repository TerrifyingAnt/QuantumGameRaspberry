# WebSocket-события

Сервер:
- ESP32: `WSController` (`controller/src/ws_controller.h`), порт **81**
- Raspberry Pi: `WsHub` (`server/src/wsHub.ts`), путь **`/ws`** на HTTP-порту (по умолчанию **8080**)

Каждое сообщение — текстовый JSON-объект:

```json
{"event": "<название>", "data": <структура зависит от события>}
```

> При добавлении новых событий или изменении существующих — обновлять этот файл.

Типы полей: `id` — число (id websocket-соединения), `name` — строка (сейчас `"player" + id`).

## Список событий

| Название | Направление | Кому | data |
|---|---|---|---|
| `setId` | подключившемуся | число | Собственный id клиента. Первое сообщение при подключении. |
| `setOnlineUsers` | подключившемуся | массив объектов | Все онлайн-пользователи на момент подключения (включая самого клиента). |
| `addOnlineUser` | всем, кроме нового | объект | Подключился новый пользователь. |
| `removeOnlineUser` | всем | число | Пользователь отключился (`data` = его id). |
| `gameStarted` | участникам | объект | Игра началась. `data` повторяет `startGame`. |
| `setGameState` | участникам | объект | Полное состояние игры (при старте и далее при изменениях). |
| `cardPlayed` | участникам | объект | Карта применена к кубиту. Вслед за ним приходит `setGameState`. |
| `gameEnded` | участникам | объект | Регистр игрока совпал с целевым, игра окончена. |
| `cardScanned` | всем | объект | Считана карта вне игры. |
| `cardWritten` | отправившему `writeCard` | — (не используется) | Карта записана в реестр. |
| `cardNeedsInput` | текущему игроку | объект | Карта считана и ждёт доп. ввод (вторая цель или грань). |
| `cantPlay` | текущему игроку | строка | Карту нельзя сыграть на выбранную цель; id причины в `data`. |

## Структуры data

### `setId`

```json
3
```

### `setOnlineUsers`

```json
[
  {"id": 0, "name": "player0"},
  {"id": 3, "name": "player3"}
]
```

### `addOnlineUser`

Приходит при подключении пользователя (всем, кроме него) и после смены
пользователем имени (тогда — всем, включая его).

```json
{"id": 4, "name": "player4"}
```

### `removeOnlineUser`

Приходит при отключении пользователя, а также перед `addOnlineUser` при
смене имени (`data` = id).

```json
4
```

### `gameStarted`

```json
{"players": [0, 3], "cubitCount": 5}
```

### `setGameState`

- `players` – список id пользователей. Индексы в этом списке используются для адресации внетри игры. 
- `registers` — регистри игроков в порядке списка `players`. Грани кубиков — строки `"+"`, `"-"`, `"i"`, `"-i"`, `"0"`, `"1"`.
- `targetRegister` – целевое состояние регистра.
- `currentPlayer` — индекс текущего игрока, `playedCards` — карт сыграно текущим игроком в этом ходу (после второй карты ход переходит следующему, и приходящее состояние уже содержит нового текущего игрока и 0).
- `skipNextTurn` — массив флагов, выровненный с `players`: помеченный барьером игрок пропустит свой следующий ход (флаг снимается при переходе).
- `kronecker` — состояние пары `kronecker_multiplication`: `null`, когда пара не активна; иначе объект `{"registers": [...], "cardsPlayed": 0|1}` — регистры, заданные первой картой пары (пустой список — пара не ограничена), и сколько карт пары применено.
- `cardsOnField` — матрица, выровненная с `registers`: для каждого игрока массив по кубитам, в ячейке — название последней карты, сыгранной на кубит, ил `null`, если на кубите нет карты. Контроллер хранит всю историю карт на каждом кубите, но в состоянии передаётся только последняя. Карта `pauli_*3` считается сыгранной на все кубиты своего окна. Кубит с последней картой `measurement` закрыт для остальных карт (см. `cards.md`).

```json
{
  "players": [0, 3],
  "registers": [["+", "i", "1"], ["0", "-", "i"]],
  "targetRegister": ["1", "0", "+"],
  "currentPlayer": 0,
  "playedCards": 0,
  "skipNextTurn": [false, false],
  "kronecker": null,
  "cardsOnField": [[null, "hadamard", null], [null, null, "pauli_x"]]
}
```

### `cardPlayed`

`target.register` — номер игрока, на чей регистр применена карта, `target.cubit` —
номер кубита, `card` — название карты (полный список — в `cards.md`).
Для карт на три кубита `cubit` — середина окна.
Для карт с доп. вводом `target` — первовая цель (выбранная `selectTarget`).
Для карт без цели (`identity`, `reshuffle`, `barrier`, `kronecker_multiplication`)
`target` — `null`.

```json
{"target": {"register": 1, "cubit": 2}, "card": "pauli_x3"}
```

```json
{"target": null, "card": "barrier"}
```

### `gameEnded`

`winnerId` — id победившего игрока (тот же id, что в списках пользователей),
`winnerName` — его имя (`"player" + id`).

```json
{"winnerId": 3, "winnerName": "player3"}
```

### `cardScanned`

Приходит при считывании любой метки, пока игра не идёт и не ожидается карта
для записи (`writeCard`). `registered` — есть ли метка в реестре; `type` —
название типа карты, только если `registered` истинно.

```json
{"registered": true, "type": "pauli_x"}
```

```json
{"registered": false}
```

### `cardWritten`

`data` не используется.

```json
null
```

### `cardNeedsInput`

Карта, требующая доп. ввода, считана и ждёт его от текущего игрока. `card` —
название карты, `need` — что требуется: `"secondTarget"` (вторая цель) или
`"face"` (выбор грани). Для `"face"` в `faces` — список допустимых граней
(строки `"+"`, `"-"`, `"i"`, `"-i"`, `"0"`, `"1"`), зависящий от состояния
кубита и карты. Вторую цель запрашивает `swap`; выбор грани —
`rotate_x`/`rotate_y`/`rotate_z` (в списке все грани, достижимые вращением
вокруг оси карты, включая текущую) и `quantum_lucky` (все шесть граней).

```json
{"card": "rotate_x", "need": "face", "faces": ["+", "i", "-", "-i"]}
```

### `cantPlay`

Отправляется текущему игроку, когда карту нельзя сыграть на выбранную цель
(или его доп. ввод оказался некорректным). При этом цель и ожидающий ввод
сбрасываются, карта не расходуется и ход не засчитывается. `data` —
текстовый id причины:

| id | Причина |
|---|---|
| `windowDoesNotFit` | x3-карта (`pauli_*3`, `hadamard_3`) на первый или последний кубит регистра — окно из трёх не помещается |
| `nothingToUndo` | `quantum_noise` на кубит, где нет последней карты |
| `notUndoable` | `quantum_noise` на кубит, где последняя карта не отменяемая (x3 или карта с выбором) |
| `identityFirst` | `identity` первой картой хода |
| `alreadyPlayed` | карта уже сыграна в этой игре (проверка повторов сейчас отключена в коде) |
| `invalidSecondTarget` | некорректная вторая цель в `cardInput` |
| `invalidFace` | некорректная грань в `cardInput` |
| `kroneckerAlreadyActive` | `kronecker_multiplication` прочитан, пока пара не закрыта |
| `registerMismatch` | вторая карта пары (или вторая цель `swap` как второй карты пары) вне регистров, заданных первой картой пары |
| `barrierAlreadySet` | `barrier`, пока следующий игрок уже помечен барьером |
| `measured` | цель (или один из задействованных кубитов карты: окно x3, цели `swap`) закрыта картой `measurement`; исключение — `quantum_noise`, снимающая measurement |

```json
"windowDoesNotFit"
```

## Клиент → сервер

Формат тот же: `{"event": "...", "data": ...}`. Сервер парсирует JSON при получении и
передаёт `data` подписчикам (`WSController::on(event, handler)`). Сообщение без
строчного поля `event` или с битым JSON отбрасывается.

| Название | data | Описание |
|---|---|---|
| `startGame` | объект | Начать новую игру. Обрабатывается, только если игра не идёт. |
| `selectTarget` | объект | Выбор кубита для следующей карты. Обрабатывается, только если отправитель — текущий игрок; пока карта ждёт доп. ввод, игнорируется. |
| `writeCard` | строка | Ожидать карту для записи в реестр. `data` — название типа карты; пустая строка отменяет ожидание (без события). |
| `giveUp` | — | Сдаться. Только участник во время игры; побеждает другой игрок (`gameEnded`). |
| `cardInput` | объект | Доп. ввод для карты, ждущей его: `secondTarget` (объект `{player, cubit}`) или `face` (строка). Только от текущего игрока. |
| `setPlayerName` | строка | Смена отображаемого имени. |
| `setOption` | объект | Изменить настройку контроллера: `{"name": "...", "value": ...}`. Применяется сразу и сохраняется в память контроллера. |
| `invitePlayer` | объект | Пригласить игрока: `{"to": <id>, "cubitCount": N}` (Raspberry Pi). |
| `inviteResponse` | объект | Ответ на приглашение: `{"from": <id пригласившего>, "accept": true\|false}` (Raspberry Pi). |

### Приглашения (Raspberry Pi)

| Название | Направление | data |
|---|---|---|
| `inviteReceived` | приглашённому | `{"from", "fromName", "cubitCount"}` |
| `inviteSent` | пригласившему | `{"to", "cubitCount"}` |
| `inviteDeclined` | пригласившему | `{"by", "byName"}` |
| `inviteCancelled` | приглашённому | `{"from"}` — отправитель отключился |
| `inviteFailed` | отправителю ответа/приглашения | `{"reason": "offline"\|"gameInProgress"\|...}` |

При `accept: true` сервер сразу шлёт `gameStarted` + `setGameState` обоим.

### `setPlayerName`

`data` — строка, новое имя. Пустая строка игнорируется. Имя обрезается до
32 символов; имена вида `player<число>` (автоматический фолбэк) занимать
нельзя — используется фолбэк `player<id>`; занятое другим игроком имя
получает числовой суффикс (`Имя2`, `Имя3`, ...). Итоговое имя клиент
узнаёт из последующего `addOnlineUser`.

При смене имени всем (включая переименованного) приходят
`removeOnlineUser` (id) и затем `addOnlineUser` (id + новое имя).

```json
"Алиса"
```

### `startGame`

`players` — id пользователей-участников, `cubitCount` — число кубиков в регистрах.

```json
{"players": [0, 3], "cubitCount": 5}
```

### `selectTarget`

`player` — номер игрока в игре (индекс в списке `players` события `startGame`),
`cubit` — номер кубита в его регистре. Можно выбирать как свои, так и чужие
кубиты. Выбор можно менять до считывания карты. Пока считанная карта ждёт
доп. ввод (`cardNeedsInput`), выбор игнорируется — цель зафиксирована.

```json
{"player": 1, "cubit": 2}
```

### `cardInput`

Доп. ввод для карты, которая после считывания ждёт его (см. `cardNeedsInput`).
Обрабатывается, только если отправитель — текущий игрок и карта действительно
ждёт ввод. Для `"secondTarget"` — объект `{player, cubit}` (номер игрока и
кубита, как в `selectTarget`); для `"face"` — строка с гранью из списка
`faces` события `cardNeedsInput`. После получения ввода карта применяется
сразу: приходят `cardPlayed` и `setGameState`.

```json
{"secondTarget": {"player": 1, "cubit": 2}}
```

```json
{"face": "i"}
```

### `writeCard`

`data` — строка, название типа карты (полный список — в `cards.md`;
`pauli_x`, `rotate_y`, `hadamard_3`, `barrier` и т.д.). Помечает контроллер: следующая метка,
считанная вне игры, регистрируется в реестре за этим типом и сохраняется в
память контроллера. Метка с другим типом перезаписывается на новый. После
записи метки отправителю приходит `cardWritten`. Пустая строка отменяет
ожидание записи: контроллер сбрасывает режим, событие при этом не
отправляется.

```json
"pauli_y"
```

### `giveUp`

`data` не используется. Отправитель сдаётся: игра заканчивается, всем
участникам приходит `gameEnded`. Победитель — следующий за сдавшимся
участник по кругу (при двух игроках — другой). Вне игры или от
не-участника игнорируется.

```json
null
```

### `setOption`

Изменяет одну настройку контроллера (`Options`, `src/options.h`). `data` —
объект: `name` — название настройки, `value` — новое значение (строка или
bool). Значение применяется сразу и сохраняется в энергонезависимую память
контроллера, переживая перезагрузку.

Неизвестное имя создаёт новую настройку. Сообщения с отсутствующим или
пустым `name`, а также со значением другого типа (число, объект, `null`)
игнорируются без ответа. Подписчик события — сам класс настроек; полный
список известных настроек и их текущее влияние — в `RULES.md`.

```json
{"name": "allowCardReplay", "value": true}
```

```json
{"name": "ssid", "value": "BoardGame2"}
```
